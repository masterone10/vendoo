# خطة العمل الهندسية: نافذة تفاصيل مؤشرات المخاطر التفاعلية (Risk Drilldown Modal) وتطابق العدادات 100%

## User Review & Critical Decisions

> [!IMPORTANT]
> **القرارات المعمارية والتصميمية المؤكدة بناءً على الإجابات:**
> 1. **النطاق الافتراضي والتطابق الرقمي 100%:**
>    - الرقم الرئيسي الكبير على كل كارت خطر في لوحة التحكم يمثل **إجمالي الطلبات الفريدة المطابقة للخطر في كامل النظام** (عبر جميع الحالات)، ليتطابق رقميًا 100% مع تبويب **«الكل»** داخل النافذة قبل الفلترة.
>    - يظهر أسفل الرقم سطر توضيحي لحصر طلبات اليوم: `اليوم: X طلب مؤكد (Printed)` يطابق تبويب **«مؤكد اليوم Printed»**.
>    - عند تطبيق أي فلتر (حالة، تاريخ، بحث)، يُعرض عدد النتائج بعد الفلترة في عداد مستقل (`تم العثور على Y من إجمالي X`).
> 2. **تحديد يوم العمل المعتمد (Africa/Cairo):**
>    - يبدأ اليوم حسابيًا من منتصف الليل `00:00:00` حتى الوقت الفعلي الحالي وفق توقيت القاهرة.
>    - تصفية «مؤكد اليوم Printed» تعتمد حصريًا على **حركة Printed الفعلية المسجلة في لوجز اليوم من 00:00 بتوقيت القاهرة** (وليس مجرد كون الحالة الحالية للطلب هي Printed منذ أسابيع).
> 3. **أعمدة متخصصة لكل خطر (Custom Columns per Risk):**
>    - **تعدد المخازن والأكواد:** كود الطلب، الحالة، المحافظة، تفكيك كامل للمخازن وأكواد التجار الرسمية المعتمدة مع المنتجات التابعة لكل مخزن، وإجمالي القيمة.
>    - **دون هاتف إضافي صالح:** كود الطلب، الحالة، الهاتف الأساسي، حالة الهاتف الإضافي (مفقود / مكرر للأساسي / صيغة تالفة)، جودة العنوان، ونسبة التسليم السابقة.
>    - **نسبة تسليم < 70%:** كود الطلب، الحالة، الهاتف، نسبة التسليم بنمط `tabular-nums` مع كسر الطلبات المنجزة `(2/5)`، نسبة الإلغاء، إجمالي طلبات العميل السابقة، وحالة آخر طلب.
> 4. **الإجراءات السريعة الثلاثة داخل النافذة:**
>    - **عرض تفاصيل الطلب الكاملة:** فتح `OrderDetailsModal` مباشرة من داخل نافذة الخطر فوقها دون فقدان التصفية أو البحث.
>    - **نسخ الأكواد دفعة واحدة:** نسخ أكواد الطلبات المفلترة المعروضة بنقرة واحدة مع إزالة التكرار وإشعار بعدد الأكواد المنسوخة.
>    - **تصدير CSV مخصص:** تصدير جدول المخاطر المفلتر بترميز `UTF-8 with BOM` يدعم العربية وأعمدة مخصصة لنوع الخطر.

## 1. Overview & Core Concept

توفير رؤية فورية وشاملة للمشرف وفريق العمليات لكافة الطلبات ذات المخاطر التشغيلية عبر نافذة تفاعلية مخصصة تفتح فور النقر على أي كارت خطر في لوحة التحكم، مع ضمان التطابق الحسابي المطلق بين واجهة العرض وقاعدة البيانات، وسرعة الاستجابة، والتفريق التام بين المخزن والتاجر.

---

## 2. User Experience & Visual Design

وفقًا لدستور التصميم Universal Frontend Design ونظام SaaS Dashboard:
- **نظام الألوان الدلالي:**
  - خلفية السطح: `bg-slate-900/95` مع إطار دقيق `border border-slate-800` وظل ناعم `shadow-2xl`.
  - اللون الأحمر القرمزي (`#F43F5E` / `text-rose-400`): لتعدد المخازن ونسب التسليم المنخفضة.
  - اللون الكهرماني (`#F59E0B` / `text-amber-400`): للهواتف غير المؤكدة أو المفقودة.
  - اللون الزمردي (`#10B981` / `text-emerald-400`): للمعدلات الإيجابية وتأكيدات الطباعة.
- **انضباط الأرقام (Tabular Figures):**
  - استخدام `font-mono tabular-nums` لكافة الأرقام، نسب التسليم `(2/5)`، الأكواد، وأرقام الهواتف.
- **تصميم التبويبات الفلترة السريعة (Segmented Controls):**
  - تبويبات نظيفة: `الكل (X)` | `مؤكد اليوم Printed (Y)` | `معلق Pending` | `قيد التنفيذ Processing` | `جديد New` | `قيد الإلغاء Canceling` | `ملغي Canceled`.
- **أزرار الإجراءات العلوية:**
  - زر `نسخ الأكواد (Copy Codes)` مع إظهار علامة تم النسخ لثوانٍ.
  - زر `تصدير CSV (Export)` مخصص لنوع الخطر.
  - زر إغلاق صريح ومفتاح `Escape`.

## 3. Key Product Decisions & Trade-Offs

1. **مسار API مخصص للخادم `/api/dashboard/risk-orders`:**
   - **النهج:** معالجة الفلترة، والبحث، والترقيم، وإثراء بيانات المخازن والتجار داخل SQLite بدلاً من تحميل آلاف الطلبات في المتصفح.
   - **النتيجة:** حماية ذاكرة المتصفح، وسرعة استجابة فائقة، وضمان التطابق مع لوجز التأكيد الأصلية.
2. **منطق مشترك موحد لتعريف المخاطر:**
   - دمج استعلامات كروت لوحة التحكم `/api/dashboard/stats` مع استعلامات النافذة `/api/dashboard/risk-orders` عبر دالة موحدة `getRiskOrdersQueryConditions(riskType)` لمنع أي اختلاف مستقبلي بين العداد والقائمة.
3. **الفصل بين كود المخزن وكود التاجر:**
   - الاعتماد على `order_items.warehouse_code` للمخزن، و `order_items.merchant_code` (من جدول المطابقة الرسمي) للتاجر، دون استنتاج عشوائي.

## 4. Technical Architecture & Data Strategy

```
┌─────────────────────────────────────────────────────────────────────────────────┐
│                              DashboardView.tsx                                  │
│  - Multi-Warehouse Card    : Shows System Total + Subtitle Today Printed        │
│  - Missing Phone Card      : Shows System Total + Subtitle Today Printed        │
│  - Low Delivery Rate Card  : Shows System Total + Subtitle Today Printed        │
│  * Clicking any card triggers -> setSelectedRiskType('multi_merchant'|...)     │
└────────────────────────────────────────┬────────────────────────────────────────┘
                                         │ opens
                                         ▼
┌─────────────────────────────────────────────────────────────────────────────────┐
│                             RiskDetailsModal.tsx                                │
│  - Header: Risk Title, Description, Total System Count (Matches Card 100%)      │
│  - Fast Filter Tabs: [ All | Today's Printed | Pending | Processing | ... ]     │
│  - Search Bar: Code, Customer, Phone, Warehouse/Merchant                        │
│  - Actions Bar: [ Copy Codes (N) ] [ Export CSV ] [ Close ]                     │
│  - Specialized Table per Risk Type                                              │
│  - Clicking any row opens -> OrderDetailsModal (layered on top safely)          │
└────────────────────────────────────────┬────────────────────────────────────────┘
                                         │ fetches
                                         ▼
┌─────────────────────────────────────────────────────────────────────────────────┐
│            GET /api/dashboard/risk-orders?riskType=&tab=&search=&page=          │
│  - Validates riskType ('multi_merchant' | 'no_extra_phone' | 'low_delivery')    │
│  - Scopes 'today_printed' using canonical_activity_events for Cairo today       │
│  - Enriches items with warehouse_name, warehouse_code, merchant_code            │
│  - Formats delivery rate with tabular fraction (e.g. 2/5 orders)                │
│  - Returns: { totalSystemMatching, filteredCount, orders, page, limit }         │
└─────────────────────────────────────────────────────────────────────────────────┘
```

## 5. Step-by-Step Implementation Plan

### المرحلة 1: الخادم ومسار البيانات المشترك (`server/routes.ts`)
1. إنشاء دالة موحدة لحساب شروط المخاطر الثلاثة:
   - `multi_merchant`: فحص `multi_merchant_flag = 1` أو وجود أكثر من كود مخزن فريد في `order_items`.
   - `no_extra_phone`: فحص `extra_phone_status = 'CONFIRMED_ABSENT'`.
   - `low_delivery`: فحص `delivery_rate < 70` مع وجود طلبات سابقة معتبرة (`delivery_rate_denom > 0 OR total_customer_orders > 0`) واستبعاد من ليس لديه تاريخ (`0/0`).
2. تحديث استعلام `/api/dashboard/stats`:
   - حساب إجمالي النظام لكل خطر (`multiMerchantTotal`, `missingExtraPhoneTotal`, `lowDeliveryRateTotal`).
   - وحساب مؤكد اليوم لكل خطر (`multiMerchantPrintedToday`, `missingExtraPhonePrintedToday`, `lowDeliveryRatePrintedToday`).
3. إضافة مسار `GET /api/dashboard/risk-orders`:
   - يدعم المعاملات: `riskType`, `tab` (`all`, `today_printed`, `Pending`, `Processing`, إلخ), `search`, `page`, `limit`.
   - يربط تفاصيل منتجات الطلب والمخازن والتجار (`order_items`).
   - يعيد `{ success: true, riskType, totalSystemMatching, filteredCount, orders, page, limit }`.

### المرحلة 2: بناء واجهة النافذة المتخصصة (`src/components/RiskDetailsModal.tsx`)
1. إنشاء المكون التفاعلي `RiskDetailsModal.tsx`:
   - شريط تبويبات الحالات مع عدادات منفصلة.
   - حقل بحث فوري مع مسح وسرعة كتابة.
   - زر نسخ الأكواد مع عداد للأكواد الفريدة المنسوخة.
   - زر تصدير CSV بترميز `\uFEFF` لفتح سليم في Excel.
   - أعمدة مخصصة لكل نوع خطر:
     * **تعدد الأكواد:** جدول المخازن والتجار والمنتجات التابعة لكل منها.
     * **دون هاتف إضافي:** رقم الهاتف الأساسي، سبب غياب الهاتف الثاني، وجودة العنوان.
     * **نسبة التسليم المنخفضة:** نسبة التسليم، كسر الطلبات السابقة `(X/Y)`، نسبة الإلغاء، وحالة آخر طلب.
2. دمج فتح `OrderDetailsModal` من داخل النافذة دون إغلاقها لضمان تجربة سلسة.

### المرحلة 3: ربط لوحة التحكم وجدول الطلبات الشامل
1. تحديث `DashboardView.tsx`:
   - عرض الرقم الرئيسي الكبير كإجمالي النظام المطابق للخطر.
   - عرض سطر توضيحي: `اليوم: X طلب مؤكد (Printed)`.
   - تفعيل النقر على أي من الكروت الثلاثة لفتح `RiskDetailsModal`.
2. تحديث `OrdersView.tsx`:
   - إضافة زر فلتر "دون هاتف إضافي" بجانب "تعدد المخازن" و"نسبة التسليم < 70%".

### المرحلة 4: حزمة الاختبارات الآلية الشاملة (`server/tests/risk_indicators_drilldown.test.ts`)
1. تشغيل الاختبار على قاعدة بيانات SQLite معزولة مؤقتة.
2. اختبار التطابق التام 100% بين عداد الكارت والتبويب "الكل".
3. اختبار عدم تكرار الطلب عند وجود عدة منتجات ومخازن (تجنب تضاعف JOIN).
4. اختبار دقة حركات "مؤكد اليوم" المسجلة باللوجز من 00:00 القاهرة.
5. اختبار فلاتر الحالات والبحث واستبعاد العملاء بدون تاريخ مسبق.
6. التحقق النهائي من خلو المشروع من أخطاء Typescript عبر `compile_applet`.

- [ ] تظهر الأعمدة المتخصصة لكل نوع خطر (مخازن وتجار / هواتف / نسب تسليم وإلغاء مع كسر الطلبات).
- [ ] النقر على أي طلب يفتح `OrderDetailsModal` فوق النافذة ويعود إليها بسلاسة.
- [ ] أزرار نسخ الأكواد وتصدير CSV تعمل بدقة وتدعم العربية.
- [ ] اجتياز كافة الاختبارات الآلية المعزولة وبناء المشروع بنجاح.
